При сбое отправки остаёмся на странице с запасными кнопками. На странице: подтверждение, кнопки звонка, Max и Telegram, отзывы, шаги заказа. noindex, в sitemap не попадает.
- 2026-11-15 — С хостинга SpaceWeb не открывается api.telegram.org (таймаут), открыты Google Apps Script, Cloudflare Workers, Yandex Cloud Functions и почта. Заявки идут в Telegram через пересылку на Google Apps Script (tools/telegram-relay.gs, секрет TG_RELAY_URL); запасной канал — почта (LEAD_EMAIL). Запасные кнопки при сбое — Telegram и MAX вместо WhatsApp (решение владельца).
- 2026-11-15 — Заявки с сайта уходят в Telegram: все формы (заявка, всплывающее окно, калькулятор) шлют POST на site/lead.php на SpaceWeb; он сохраняет заявку в lead-data/leads.csv на хостинге (копия в РФ, закрыта от браузера) и пересылает боту. Токен и chat_id — секреты GitHub TG_BOT_TOKEN, TG_CHAT_ID (по желанию LEAD_EMAIL — запасная почта), deploy-ftp.yml пишет из них lead-config.php, в git его нет. Защита от спама: поле-ловушка и не больше 5 заявок с адреса за 10 минут. Если отправка не удалась — кнопка WhatsApp с готовым текстом. Цель Метрики lead_form срабатывает только после успешной отправки.
- 2026-11-13 — Под нейроответы (Алиса AI, обзоры Google): на страницах услуг и городов блок «Коротко» сразу под первым экраном (цена от, сушка, выезд, средства — только факты, уже написанные на сайте; сушка из DRY_TIME, где данных нет, строки нет); в FAQ услуг добавляются недостающие вопросы о цене (из price_rows), сушке и безопасности для детей и животных, на «Вопросах и ответах» они не дублируются; прайс на услугах теперь таблица <table> (вид прежний); LocalBusiness стал DryCleaningOrLaundry с описанием и есть на каждой услуге, Service ссылается на него по @id и перечисляет цены по строкам прайса. Дата «Цены актуальны на…» и dateModified уже были.
- 2026-11-12 — Метрика запускается сразу при загрузке, без ожидания «Принять» (решение владельца: иначе Директ не видит заявки и автостратегия плохо учится).
